# H264 지속 worker 조건 연구 1단계 결과

## 환경

- 측정 시각: 2026-09-27 07:50~07:52 KST
- Jetson Xavier NX
- 전력 모드: `MODE_20W_6CORE` / profile 8
- CPU governor: `schedutil`
- 운영 `main.py` PID 5563은 시험 전후 동일하게 실행 중
- 운영 파일, 카메라, 전력·클럭 설정 변경 없음
- 입력: 동일 실제 영상에서 추출한 81프레임, 960×540, 9fps
- 고정 seed 무작위 순서, 조건별 20회, 회차 간 0.25초 idle

`jetson_clocks --show`는 root 권한이 필요해 실행할 수 없었으며, 실제 GPU/CPU/EMC
상태는 `tegrastats.log` 원본으로 기록했다.

## H264 시간 분해 중앙값

| 구간 | 4Mbps | 1.2Mbps |
|---|---:|---:|
| raw 준비 | 0.145초 | 0.144초 |
| worker 내부 encode | 0.818초 | 0.821초 |
| IPC/poll/state·response fsync 추정 | 0.302초 | 0.305초 |
| finalize | 약 0.007초 | 약 0.002초 |

병목 우선순위는 worker encode, **미분해 잔차**, raw 준비 순이다. 잔차는
상태파일 락·fsync, stdin 전달, worker JSON parse, response fsync·rename,
10ms polling을 모두 포함하므로 순수 IPC 시간으로 해석하지 않는다. seq28의 잔차
0.158초는 다른 회차 약 0.30초 대비 이상치이며 원인은 후속 세부 계측 대상이다.

## raw 쓰기 방식

| 방식 | n | p50 | p95 | max |
|---|---:|---:|---:|---:|
| `tobytes()+write()` | 20 | 0.135초 | 0.142초 | 0.145초 |
| `memoryview()+writev()` | 20 | 0.120초 | 0.130초 | 0.137초 |

`writev`는 raw 구간 중앙값을 약 14.7ms 줄였지만 전체 H264 약 1.27초의 약 1.2%다.
복잡성 대비 20% 목표에 미치는 영향이 작으므로 운영 구현 후보에서 제외한다.

짧은 시험에서 누적 메모리·swap 증가나 고온은 관찰되지 않았다. main.py 프레임
드롭 여부는 별도 운영 로그가 없어 이 단계에서 입증하지 못했다.
시험 시작 전부터 swap 약 1.06GB가 사용 중이었으므로 2단계 유지보수 시험 전
메모리·swap 상태를 다시 확인한다.
