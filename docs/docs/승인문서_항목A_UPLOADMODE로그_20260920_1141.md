## 승인 범위

`보완계획서_Codex검수후속_20260920.md`의 **항목 A만** 승인한다. 항목 B(배터리 단위 판정/RTL 일관성)는 이 승인에 포함되지 않으며, 실배터리 연결 후 별도 승인 절차를 거친다.

## 승인 사유

1. 비행 제어·안전 로직을 변경하지 않는 진단 로그 보강이다(계획서 §7 "비행 제어 동작을 바꾸지 않는 진단 로그 보강이므로 독립적으로 진행할 수 있다").
2. 선행조건이 없다 — 실배터리 연결, 비행팀 합의 등 외부 조건에 의존하지 않는다.
3. 검수(2026-09-20 `검수보고서_Codex수정건_20260920_1111.md`)에서 실제 결함으로 확인된 가시성 공백(`UPLOAD_MODE`가 조용히 A로 되돌아가도 실제 이상 트리거 전까지 알 수 없음)을 직접 해소한다.

## 승인 조건 (계획서 §3 그대로 적용)

1. 수정 전 `main.py`(및 필요 시 `uploader.py`) 로컬 백업(`*.bak_YYYYMMDD설명`)
2. `main.py`가 `uploader.py`의 검증된 `UPLOAD_MODE`/`ANALYZE_URL`/`DRONE_ID`를 참조
3. `if __name__ == "__main__":` 진입 직후, 카메라·TensorRT 초기화 **이전에** 설정 로그 1회 출력 (비밀값·장치 키 제외)
4. A모드는 `WARNING`, B모드는 `INFO`로 구분 표시
5. 유효하지 않은 `UPLOAD_MODE` 값은 기존 `uploader.py` 검증 로직대로 시작 단계에서 즉시 실패

## 시험 요구사항 (계획서 §3.3 그대로 적용)

| 시험 | 기대 결과 |
|---|---|
| `UPLOAD_MODE=B` 격리 테스트 | B 설정 로그 1회, 경고 없음 |
| `UPLOAD_MODE=A` 격리 테스트 | A 설정 로그 + 영상 전용 모드 경고 |
| `UPLOAD_MODE=invalid` 격리 테스트 | 카메라 초기화 전 `ValueError`로 명확히 종료 |
| `restart_component.sh main` 실기 확인 | 실제 프로세스 환경과 시작 로그 모두 B |

추가로 기존 `130_upload_form_contract_offline.py` 4건이 계속 통과해야 하며, Python 문법 검사와 최근 로그(`ERROR`/`CRITICAL`/`Traceback`) 확인을 거친다.
