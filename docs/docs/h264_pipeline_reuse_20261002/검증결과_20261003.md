## 핵심 해석

지속 pipeline은 파일 무결성과 복구 면에서는 구현 가능했지만, EOS가 없는 열린 NVIDIA encoder 경로가 9초 클립을 거의 실시간 속도로 처리했다. 요청별 pipeline을 EOS로 끝내는 기존 worker보다 약 9.1배 느리므로 런타임 지연 제거라는 목적을 달성하지 못한다.

`splitmuxsink`도 같은 속도 문제를 보였고 GOP 기준 분할 때문에 요청 경계가 1프레임씩 이동했다. 마지막 요청을 즉시 완결하려면 EOS 또는 다음 keyframe이 필요해 “요청 종료 즉시 독립 MP4 반환” 조건과 맞지 않는다.
