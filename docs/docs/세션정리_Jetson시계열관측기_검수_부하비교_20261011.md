- 정리일: 2026-10-11 (KST)
- 실제 시험일: 2026-10-10 (KST)
- 대상: `E:\univ\testwatcher`
- 목적: 로컬 PC가 SSH로 Jetson 운영 자원을 시계열 관측하되, 관측 자체가 Jetson 운영 성능을 왜곡하지 않는지 확인

## 1. 최종 결론

Jetson 시계열 관측기를 **1초 간격 운영 부하시험용 관측 도구로 승인**한다.

동일 영상 세트의 watcher ON/OFF 대응 시험에서 VadCLIP 추론, H264 인코딩, 동기 업로드, RSS·Swap 변화와 오류 발생에 운영상 유의한 성능 저하가 관찰되지 않았다. 현재 구조와 수집 범위를 유지할 수 있다.

이번 결과는 통계적 동등성 검정 결과가 아니다. 분산·신뢰구간·동등성 검정을 수행하지 않았으므로 판정 문구는 다음으로 제한한다.

> 이번 20분 대응 시험에서 watcher로 인한 운영상 유의한 성능 저하가 관찰되지 않았다.

장기 메모리 누수 여부는 20분 시험 두 번으로 확정하지 않으며 별도 장시간 시험으로 분리한다.

## 3. 검수와 보완 이력

### 3.1 로컬 중심 구조 확정

최초 구현은 Jetson에 Python 원격 sampler를 실행했다. “Jetson 부담을 줄이기 위해 로컬에서 실행한다”는 목적에 맞춰 원격 Python 파싱·JSON 생성·통계 계산을 제거하고 최소 bash relay로 교체했다.

60초 무부하 smoke에서 다음을 확인했다.

- bash sampler CPU 평균 4.24%, 최대 5.72%, RSS 최대 3.07 MiB
- `tegrastats` CPU 평균 0.25%, RSS 최대 0.50 MiB
- 요청한 60초와 실제 sampling 구간을 분리해 기록
- SSH 준비시간과 cleanup 시간을 sampling 시간에서 분리
- sampler와 `tegrastats` 잔존 0건
- 운영 `main.py`, H264 worker, `command_receiver.py` 생존·무변경

### 3.2 PID 재탐색 보완

Codex 재검수에서 다음 상태 전이 문제를 발견해 보완했다.

- main 교체 직후 H264 후보를 찾지 못하면 기존 H264 PID를 즉시 무효화
- 재탐색 실패에도 20초 backoff 예약
- 재탐색 명령이 출력한 EVENT를 `events.jsonl`에 실제 보존
- H264 override에 `__CLEARED__` sentinel을 쓰고 one-shot으로 적용 후 삭제
- 새 PID의 starttime을 재탐색 시점에 함께 확보

### 3.3 전환 표본 일관성 보완

- override 파일을 임시파일에 완전히 쓴 뒤 같은 디렉터리에서 `mv -f`로 원자적으로 게시
- 한 틱 시작 시 `observed_main_pid`와 `observed_h264_pid`를 고정해 PID와 `/proc` 통계가 섞이지 않게 처리
- 이전 starttime을 현재 통계로 덮어쓰기 전에 보존해 `old_starttime_ticks`와 `new_starttime_ticks`를 정확히 기록

### 3.4 게시 실패 처리 보완

마지막 검수에서 임시파일 쓰기는 성공했지만 `mv -f`만 실패하는 경로가 발견됐다. 공용 `publish_override(tmp, final, value)` 함수로 다음을 보완했다.

- write 실패: `override_publish_failed / write`
- rename 실패: `override_publish_failed / rename`
- 어느 단계가 실패해도 임시파일 정리
- 게시 실패 시 성공 PID/starttime을 비워 로컬 watcher가 새 PID로 잘못 전환하지 않음
- 기존 재탐색 실패·backoff 경로 재사용

최종 Codex 판정은 **APPROVED**이며, 기록은 `E:\univ\testwatcher\Codex_Jetson_시계열관측기_최종승인_20261010.md`에 있다.
