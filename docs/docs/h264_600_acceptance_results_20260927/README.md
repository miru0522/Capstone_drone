# H264 600 kbps 채택 시험 결과 (2026-09-27)

## 결론

**H264 600 kbps는 절대 지연 0.1초 이상 단축 기준을 통과했으며 교체 후보로 채택한다.**

전체 100회 집계에서 mp4v 대비 p50 0.426초, p95 0.739초 단축됐다. 고정 참조 영상 `kakao_20260914.mp4`도 p50 0.264초, p95 0.278초 단축됐고 다른 고정 참조 영상은 p50 0.463초, p95 0.408초 단축됐다. 모든 집계 지점에서 0.1초 이상 단축 기준을 충족했다.

인코딩 성공률, 프레임 디코딩, 지속 워커 재사용, 운영 `main.py` 생존, 임시 파일 정리 및 온도도 모두 정상이다. 종전 문서의 20% 기준은 기존 연구 목표를 합격 조건으로 잘못 적용한 것이며, 실제 교체 요구인 0.1초 이상 단축 기준으로 판정을 바로잡았다. 이 판정은 인코딩 구간에 한정하며 서버 수신·추론을 포함한 종단 지연 개선을 주장하지 않는다.

## 판정과 교체 조건

고정 참조 영상 각각에서 p50과 p95가 모두 0.1초 이상 단축돼야 한다는 기준을 적용한다. 두 참조 영상과 전체 집계가 모두 통과했다.

2026-09-29 전체 30영상 픽셀 품질 시험에서 H264 600 kbps 평균은 PSNR 36.36 dB, SSIM 0.95575로 집계 기준을 통과했다. 영상별 평균 PSNR은 30개 모두 30 dB 이상이었고, 영상별 평균 SSIM은 23/30개가 0.95 이상이었다. 기존 mp4v도 영상별 평균 SSIM이 27/30개만 0.95 이상이므로 입력별 편차는 운영 관찰 항목으로 남긴다. 시험 프로그램에 있던 영상별 전건 gate는 두 코덱 모두 false였으며, 본 판정은 사전에 합의한 전체 평균 기준이다.

기존 서버 VideoMAE 원시 자료를 2026-09-29에 다시 집계한 결과, mp4v와 H264 600 kbps의 직접 짝 비교는 28/30이다. `Assault006_x264.mp4`와 `Burglary017_x264.mp4`의 H264 600 kbps 요청이 180초 ReadTimeout으로 끝났고, 전자는 동일 내용의 중복 파일에서 성공했지만 후자는 미커버 상태다. `Abuse028_x264.mp4`는 경보 등급 `CRITICAL`은 유지됐으나 categoryId가 1에서 2로 바뀌었다. 따라서 서버 판정을 30/30 검증 완료로 간주하지 않으며, 미커버와 카테고리 변화는 승인 시 명시적으로 수용하거나 별도 승인 후 재시험해야 한다.

교체 설정은 `CLIP_ENCODER=h264`, `H264_BITRATE=600000`이다. `maxperf-enable=true`는 0.1초 기준 충족에 필요하지 않으므로 이번 교체 후보에 포함하지 않는다.
