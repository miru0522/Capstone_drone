# VadCLIP 1차 이상 점수 전송 수정 보고서

- 작업일: 2026-09-20
- 대상: Jetson `~/drone_2026/code/`
- 목적: 관제 화면 사고 상세에서 1차 이상 점수(VadCLIP)가 `측정값 없음`으로 표시되는 문제 해결
- 실기 브랜치: `vadclip-v4-20260831`

## 1. 문제 현상

2차 분류(VideoMAE) 점수, 사고 영상, TTS는 정상적으로 처리되지만 1차 이상 점수만 관제 화면에 표시되지 않았다. Jetson 로그에는 VadCLIP 트리거 점수(`score=0.xxx`)가 기록되고 있어 모델 추론 이후의 전송 경로를 점검했다.

## 2. 원인 확인

`main.py`는 이상 트리거 시 다음과 같이 점수를 정상 전달하고 있었다.

```python
upload_clip_sync(snapshot, anomaly_score=score)
```

그러나 `uploader.py`는 `UPLOAD_MODE=A`일 때 영상 파일만 전송한다. 기존 실행 스크립트가 `UPLOAD_MODE`를 설정하지 않았으므로 `uploader.py`의 호환용 기본값 `A`가 적용됐고, `anomaly_score` 폼 필드가 서버에 전달되지 않았다.

B 모드에도 별도 데이터 품질 문제가 있었다. 점수가 `None`이면 `0.0`을 전송해 서버가 다음 두 상태를 구분할 수 없었다.

- 점수를 계산하거나 전달하지 못함: 필드 없음
- 실제 VadCLIP 점수가 0점임: `anomaly_score=0.0`

## 3. 수정 내용

| 파일 | 변경 내용 |
|---|---|
| `uploader.py` | `_build_form_data()`를 추가해 동기·비동기 업로드가 같은 폼 생성 규칙을 사용하도록 했다. 점수가 `None`이면 키를 생략하고, 실제 `0.0`은 보존한다. `UPLOAD_MODE`를 대문자로 정규화하고 A/B 이외 값은 시작 시 거부한다. Jigsaw 탑재 이후 사용 예정이라는 오래된 설명을 현재 VadCLIP 운영 방식에 맞게 수정했다. |
| `restart_component.sh` | 별도 환경 설정이 없으면 `UPLOAD_MODE=B`를 내보내도록 했다. `main.py`만 교체 기동할 때도 설정이 유지된다. |
| `start_all.sh` | 전체 파이프라인 기동 시 기본 `UPLOAD_MODE=B`를 내보내도록 했다. |
| `130_upload_form_contract_offline.py` | 실제 서버 요청 없이 모드와 multipart 폼 데이터 계약을 검증하는 테스트 4건을 추가했다. |

`uploader.py` 자체의 기본값 `A`는 구버전 호환용으로 유지했다. 정식 운영 진입점인 두 실행 스크립트에서 B를 기본값으로 명시했으며, 운영자가 외부에서 `UPLOAD_MODE=A`를 지정하면 기존 영상 전용 모드로 전환할 수 있다. 따라서 `python3 main.py`를 실행 스크립트 없이 직접 시작하면 A 모드가 적용될 수 있다.

## 4. 배포 절차와 안전 조치

1. 수정 전 원본 세 파일을 Jetson에 백업했다.
   - `uploader.py.bak_20260920_scoreform_before`
   - `restart_component.sh.bak_20260920_uploadmode_before`
   - `start_all.sh.bak_20260920_uploadmode_before`
2. 전체 드론 파이프라인을 재시작하지 않고 `./restart_component.sh main`으로 VadCLIP `main.py`만 재시작했다.
3. `mavsdk_server`, `telemetry_sender.py`, `command_receiver.py` 등 다른 팀원 담당 프로세스는 중단하지 않았다.
4. 가짜 사고 업로드는 관제 서버에 불필요한 이벤트를 만들 수 있어 실행하지 않았다.

3. 실제 `anomaly_score=0.0`이 문자열 `"0.0"`으로 보존되는지 확인
4. 실제 `anomaly_score=0.4073`이 문자열 `"0.4073"`으로 보존되는지 확인

## 7. 리뷰 시 확인할 사항

1. `None`일 때 필드 생략과 실제 `0.0` 보존이 서버 저장 규칙과 일치하는지
2. 운영 프로세스가 반드시 `start_all.sh` 또는 `restart_component.sh main`을 통해 시작되는지
3. 다음 실제 이상 트리거에서 `/analyze-video` 요청에 `drone_id`와 `anomaly_score`가 포함되고 관제 사고 상세에 1차 점수가 표시되는지
4. 점수 미산출 상황에서는 서버와 관제가 이를 실제 0점으로 저장하지 않고 미측정으로 남기는지
