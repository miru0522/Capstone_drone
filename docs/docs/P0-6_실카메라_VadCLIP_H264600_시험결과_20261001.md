## 1. 결론

P0-6의 H264 기능 판정은 **통과**로 본다.

- 독립 실행 3회 중 1·3차에서 실제 CSI 카메라, 실제 VadCLIP 추론, H264 600 kbps 인코딩을 동시에 실행했다.
- 두 성공 실행 모두 cold 1회와 같은 worker의 warm 10회를 완료했다.
- 22개 출력 모두 81프레임으로 디코딩됐고, 각 실행 안에서 worker PID가 유지됐다.
- VadCLIP 추론은 각 성공 실행에서 6회 완료됐고 연속 추론 실패는 0회였다.
- 이전 5.193초 사례와 같은 cold 지연은 5.940초와 6.082초로 다시 확인됐다. 이는 계획에서 자동 실패 조건으로 두지 않았으며, 프로세스별 인코더 웜업을 후속 별도 커밋으로 적용해야 한다는 근거가 됐다.
- warm 인코딩 중앙값은 1차 1.352초, 3차 1.348초였다.

다만 2차 실행에서 H264 호출 전 CSI/Argus가 연속 메모리 부족으로 중단됐다. 동일한 시험을 즉시 연속 실행할 때 나타난 Jetson 메모리 단편화 위험으로 기록한다. 운영 후보의 H264 인코더 실패로 분류하지 않지만, 실제 적용 후 main 재시작을 연달아 반복하지 않고 카메라 초기화 실패 로그를 운영 관찰 항목에 포함해야 한다.

## 2. 시험 안전장치

시험 전용 `p0_live_main.py`는 후보 `main.py` 복사본에만 one-shot hook을 삽입했다.

- 실제 CSI 파이프라인과 실제 VadCLIP 모델을 사용했다.
- `_handle_anomaly_score()`는 점수와 시간을 기록하기만 했다.
- anomaly threshold, hover 상태, 비행 명령을 호출하지 않았다.
- 스트리밍 상태 파일, 테스트 주입 상태 파일, hover 상태 파일, 주기녹화 상태 파일을 모두 `/tmp` 전용 경로로 격리했다.
- H264 raw 파일은 `/dev/shm`, 결과와 상태는 `/tmp/h264_600_reapply_20260930/`에만 생성했다.
- 운영 `main.py`, `uploader.py`, 시작 스크립트는 변경하지 않았다.

### 3.1 실제 추론과 인코딩 겹침

타임스탬프 구간 교차로 확인한 결과는 다음과 같다.

- 1차: cold 1회와 warm 4회가 VadCLIP 추론과 겹쳤다.
- 3차: cold 1회와 warm 4회가 VadCLIP 추론과 겹쳤다.
- 겹침이 있는 상태에서도 파일 손상, worker 교체, 추론 중단은 없었다.

### 3.2 자원 관찰

| 실행 | RAM 최대 | swap 최대 | GR3D 최대 | 비고 |
|---|---:|---:|---:|---|
| 1차 | 5388/6833 MB | 47 MB | 99% | 기능 PASS |
| 2차 | 4849/6833 MB | 45 MB | 99% | `lfb 1x2MB` 구간에서 Argus native buffer 할당 실패 |
| 3차 | 5320/6833 MB | 298 MB | 99% | 기능 PASS, 정상 종료 |

2차는 총 사용 RAM만 보면 상한에 닿지 않았으나 연속 메모리 블록이 고갈됐다. 로그에는 다음 순서가 남았다.

1. CSI 첫 프레임 및 VadCLIP 초기화·웜업 완료
2. 첫 실제 추론 0.582초 완료
3. `NvMapMemAllocInternalTagged ... error 12`
4. Argus `InsufficientMemory`, `IImageNativeBuffer not supported by Image`
5. 링버퍼가 81프레임을 채우지 못해 90초 준비 제한 초과

시험 프로세스 종료 뒤 메모리는 `897/6833MB`, `lfb 330x4MB`로 회복됐고 세 번째 실행은 정상 통과했다.

## 4. 판정과 다음 단계

### 통과 근거

- 실제 카메라와 실제 VadCLIP을 사용한 두 독립 성공 실행
- H264 600 출력 22개 전부 81프레임
- 실제 추론 겹침 확인
- warm worker 재사용 확인
- 성공 실행의 추론 실패 0회
- 3차 runner 정상 종료 및 잔존 프로세스 0개

### 남은 위험과 처리

1. **cold 지연**: 첫 호출은 약 6초다. 기본 H264 600 재적용과 섞지 않고, 계획서 9절의 프로세스별 `warmup_clip_encoder()`를 별도 커밋으로 구현한다.
2. **연속 재시작 후 Argus 메모리 단편화**: 이번에 1회 확인됐다. 실제 전환 시 재시작 직전 프로세스 잔존과 `tegrastats`의 RAM/lfb를 확인하고, 카메라 초기화 실패 시 인코더가 아니라 Argus 자원 문제로 구분한다.
3. **1차 종료 지연**: 시험 harness의 종료 문제다. 3차에서 결과 기록 후 카메라 해제와 명시 종료를 적용해 return code 0으로 확인했다.
4. **서버 통합**: P0-7은 아직 실행하지 않았다. 실제 서버 전송은 대상 영상·횟수·엔드포인트를 제시하고 별도 승인 후 진행한다.
