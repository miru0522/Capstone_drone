# Jetson 영상 주입 및 서버 로깅 시험 — 2026-09-25

사용자가 드론 영상 주입 시험을 요청했고, 실제 호버 요청 경로와 지상 안전 상태 확인 질문에 동의한 뒤 실행했다. 코드·임계값·안전 로직을 변경하거나 프로세스를 재시작하지 않았다.

## 결과

**영상 주입과 VadCLIP 이상 트리거는 성공했으나, 영상 업로드가 타임아웃되어 서버 분석 로깅 E2E는 미검증이다.** 실제 호버 요청은 IDLE 상태 안전 검사에서 거부됐다. 실제 비행 호버 성공이나 VideoMAE/Qwen 실행 성공으로 간주하지 않는다.

## 해석과 검증 한계

- 드론 main.py의 '호버링 유지 중' 문구는 성공 증거가 아니다. 실제 요청 상태 파일에서 거부를 확인했다.
- nginx 수신 단계에서 실패했고, 시험 시간대 AI 컨테이너 로그 출력은 없었다. 백엔드 analysis_id 로그도 검색되지 않았다. 분석 요청이 AI로 전달된 증거가 없어 점수·Qwen·DB·event_id 연결은 이번 시험으로 검증하지 못했다.
- 업로드 타임아웃의 근본 원인(네트워크 전송 정체, 프록시 수신 설정 등)은 아직 확정하지 않았다. 로깅 코드 결함으로 단정하지 않는다.
- 주입은 자동 종료되어 실제 카메라 입력으로 복귀했고, main.py의 추론·프레임 처리 로그가 계속 기록됐다. 안전 상태를 강제로 변경하거나 호버 거부를 우회하지 않았다.

## 증거

[시험 증거 폴더](server_logging_review_20260925/injection-test/)에 Jetson 주요 이벤트, 요청 상태, nginx 로그를 보존했다. AI/백엔드 분석 로그 파일은 해당 시간대 출력이 없어 비어 있다. 서버 수집 범위는 UTC 12:44~12:49(한국 시각 21:44~21:49)이다.

## 다음에 할 일

1. Jetson→nginx 약 8.3MB 업로드가 정체된 이유를 네트워크·nginx 수신 설정 양쪽에서 진단한다.
2. 원인 해결 후 영상 주입 시험을 재수행해 analysis_id가 AI에서 백엔드까지 이어지는지, VideoMAE/Qwen/TTS/DB/STOMP 단계 및 event_id가 남는지 확인한다.
3. 이번 IDLE 거부는 안전 검사 작동 확인이며 실제 호버 동작 검증을 대신하지 않는다.
