## 배경

Jetson 운영 checkout은 `2007b8f`이며 H264 적용이 `77944d4`에서 다시 롤백된 상태입니다.
운영 `main.py`에는 별도 팀 작업인 `PeriodicRingRecorder`가 미커밋 상태로 있으므로 과거
H264 candidate `main.py`를 통째로 복원하면 안 됩니다.

이번 후보는 다음 방식으로 만들었습니다.

- `uploader.py`, `h264_encoder_worker.py`, `start_all.sh`, `restart_component.sh`:
  승인 커밋 `7f273bb` Git blob과 기존 manifest/candidate의 SHA-256 3자 일치 파일
- `main.py`: Jetson 현재 미커밋 파일을 기준으로 `CLIP_ENCODER` import와 시작 설정
  로그만 병합
- 운영 checkout 수정, main 재시작, 카메라 실행, 서버 전송 없음

## 반드시 확인할 항목

1. `evidence/main_jetson_current_before_h264.py`와 `candidate/main.py`의 diff가 허용된
   H264 설정 로그 변경뿐인지 확인해 주세요.
2. `PeriodicRingRecorder`와 관련 import·초기화·종료 코드가 모두 보존됐는지 확인해 주세요.
3. `manifest.json`의 baseline/candidate/승인 source 해시 관계가 타당한지 확인해 주세요.
4. H264 persistent worker의 timeout·process group 종료·임시 파일 정리·상태 기록에
   회귀가 없는지 확인해 주세요.
5. mock 부모 통합 시험이 `anomaly_score` 유무와 `drone_id` 폼을 정확히 검증하는지
   확인해 주세요.
6. 4 Mbps 주기 녹화와 600 kbps 이상 클립 동시 인코딩 10회 결과에서 운영 차단
   문제가 있는지 확인해 주세요.
7. 다음 단계인 실제 CSI 카메라·VadCLIP·H264 P0-6으로 넘어가도 되는지 판정해 주세요.
