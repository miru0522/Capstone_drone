# 링버퍼 영상 주입 가이드 (간단판)

실행 중인 `main.py`에 카메라 대신 지정 영상을 일정 시간 흘려보내 VadCLIP 트리거를
강제로 재현하는 방법. main.py 재시작 불필요, 실시간으로 바로 적용됨.

## 0. 전제조건
`main.py`가 이미 떠있어야 함 (`./start_all.sh`로 기동된 상태).
```bash
ssh Jetson 'ps -p $(cat drone_2026/code/logs/main.pid) -o pid,etime,stat'
```

## 1. 영상 준비 & 전송
해상도/fps 아무거나 상관없음(자동으로 카메라 해상도·9fps 기준 리샘플링됨).
```bash
scp <로컬영상경로> Jetson:/home/hpc/drone_2026/video/<파일명>.mp4
```

## 2. 주입 실행
```bash
ssh Jetson 'cd drone_2026/code && python3 test_trigger_inject.py /home/hpc/drone_2026/video/<파일명>.mp4 --duration 20'
```
- `--duration`: 몇 초간 카메라 대신 재생할지 (기본 15초, 영상이 짧으면 반복재생)
- 지정 시간 끝나면 자동으로 실제 카메라로 복귀함

## 3. 결과 확인
`duration + 10초` 정도 기다린 후:
```bash
ssh Jetson 'cd drone_2026/code && grep -E "TestInject|이상 감지 트리거|서버 응답" logs/main.log | tail -20'
```
- `score`가 threshold(`0.4073`) 넘으면 트리거 → 호버링 → 업로드 → 서버판정 → 이벤트 등록까지 자동 진행
- 안 넘으면 트리거 없이 조용히 원래 카메라로 복귀 (정상 동작, 고장 아님)

## ⚠️ 주의
- **mavsdk_server가 Pixhawk에 연결된 상태에서 트리거되면 실제 `action.hold()`(호버링)가 기체로 나감.** 시동 꺼짐/고정 상태인지 미리 확인.
- 재시작 직후 신호파일에 이전 요청이 남아있으면 새 명령 전 잠깐 옛 영상이 먼저 재생될 수 있음(무해, 신경 안 써도 됨).
