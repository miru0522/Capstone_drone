Qwen lock 대기는 평균 0.066ms로 동시 요청 대기 병목은 없었다. 이번 배치의 주된 병목은 Qwen 생성이다. 이전 이벤트 323에서는 TTS가 7.35초였지만 이번 5건은 평균 0.468초로 크게 짧았다.

5건 모두 다음 상태로 종료됐다.

- AI 응답 및 백엔드 제출 HTTP 200
- DB 저장 완료, 이벤트 ID 325~329 생성
- STOMP `/topic/events` 발행 완료
- Qwen 파싱 fallback 없음, 품질 상태 `normal`
- 구조화 로그 누락 카운터 0
- 요청 오류·전송 실패 0건

다만 STOMP 로그의 `screen_display`는 `unknown`이므로 실제 관제 화면 표시를 증명하지는 않는다. 또한 호버 요청 5건이 Jetson `main.log`에 기록됐지만 같은 requestId의 수락·거부 결과가 `command_receiver.log`에 남지 않았다. 당시 공유 상태는 `IDLE`이므로 실제 호버 수행 증거로 간주할 수 없으며, 호버 IPC 처리와 결과 로그를 별도로 점검해야 한다.

파일명에 높은 confidence가 표시된 앞쪽 폭력 영상 5개는 이번 VadCLIP 실행에서 트리거되지 않았다. 파일명의 confidence가 현재 탑재 모델의 결과인지, 256-frame 특징 버퍼와 9초 주입 방식이 판정에 어떤 영향을 주는지는 별도 검증 대상이다.
