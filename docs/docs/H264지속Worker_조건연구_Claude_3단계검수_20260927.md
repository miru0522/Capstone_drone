# H264 지속 worker 조건 연구 Claude 3단계 검수

## 최초 결과 검수

- 판정: **REVISE**
- 원시 40건과 p50/p95/max, 파일 크기, 메모리, 운영 로그 수치 재현
- p50 중앙값과 p95 올림 순위법의 정의 차이를 문서화하도록 요구
- `jetson_clocks --show` 캡처 누락 지적
- "운영 무교란" 표현을 실제 확인 범위인 "운영 이상 이벤트 무중첩"으로 축소 요구

## 반영

- 올림 순위 p95 28.78%와 선형보간 p95 27.42%를 병기
- `jetson_clocks --show`를 실행해 root 권한 필요 출력을 보존하고, 고정 클럭과
  스로틀링을 확인하지 못한 한계를 명시
- main.py 생존 및 이상 트리거·mp4v 인코딩·업로드 시작 0회만 확인했다고 정정
- 단일 영상, n=20, cold 회차와 tail 민감성 한계 명시

## 재검수

- 판정: **APPROVE (1단계 선별 범위 한정)**
- H264 1.2Mbps, persistent worker, state/response `/dev/shm` 후보 채택
- mp4v 대비 p50 46.01%, p95 27.42~28.78%, 파일 크기 54.95% 감소 확인
- 실제 운영 전환은 승인하지 않음

## 2단계 전 남은 MUST

1. sudo 권한 또는 root 불필요 대안으로 실제 클럭 값 확보
2. 비행 없는 유지보수 시간에 mp4v/H264 각 100회·30분 반복
3. cold/warm, RSS, fd, thread, worker 재시작, 손상 파일 추세 확인
4. PSNR/SSIM 및 서버 판정 품질 비교
5. tmpfs ENOSPC·재부팅 상태 소실 정책과 실제 업로드 종단 지연 검증
