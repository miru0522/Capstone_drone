# VadCLIP 1차 이상 점수 전송 수정 세션 정리 (2026-09-20)

## 증상과 원인

- 관제 화면 사고 상세에서 1차 이상 점수(VadCLIP)가 `측정값 없음`으로 표시됐다.
- `main.py`는 `upload_clip_sync(snapshot, anomaly_score=score)`로 점수를 전달하고 있었다.
- `uploader.py`의 기본 `UPLOAD_MODE`가 `A`여서 영상만 전송했고, 점수 인자를 폼 데이터에 넣지 않았다.
- B 모드에서도 점수가 `None`이면 `0.0`을 전송해 서버가 미측정과 실제 0점을 구분할 수 없었다.

## 반영 내용

1. `start_all.sh`와 `restart_component.sh`가 별도 설정이 없을 때 `UPLOAD_MODE=B`를 내보내도록 했다.
2. `uploader.py`에서 모드를 대문자로 정규화하고 `A` 또는 `B`만 허용한다.
3. B 모드 폼 데이터 생성 로직을 `_build_form_data()`로 통합했다.
4. `anomaly_score is None`이면 `anomaly_score` 키를 생략한다.
5. 실제 점수 `0.0`은 그대로 전송하므로 미측정과 0점을 구분한다.
6. Jigsaw 탑재 이후 사용 예정이라는 오래된 설명을 현재 VadCLIP 전송 방식에 맞게 수정했다.
7. `130_upload_form_contract_offline.py`를 추가해 모드와 폼 데이터 계약을 회귀 검증한다.

## 검증 결과

- `uploader.py` Python 문법 검사 통과.
- `start_all.sh`, `restart_component.sh` 셸 문법 검사 통과.
- 오프라인 계약 테스트 4건 통과:
  - B 모드 활성화
  - `None`일 때 점수 키 생략
  - 실제 `0.0` 보존
  - 실제 `0.4073` 보존
- `restart_component.sh main`으로 VadCLIP `main.py`만 재시작했다.
- 실행 프로세스 환경에서 `UPLOAD_MODE=B`를 확인했다.
- 재시작 후 CSI 카메라, TensorRT/VadCLIP 추론, 약 9~10 FPS 처리가 정상이며 장시간 실행 중 오류가 확인되지 않았다.
