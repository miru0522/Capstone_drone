# P0-7 최소 서버 통합 시험 승인 요청

## 1. 실제 전송 범위

- 원본 영상: `/home/hpc/drone_2026/video/ucf/Assault006_x264.mp4`
- 원본 정보: MPEG-4, 320×240, 30 fps, 9.0초, 270프레임, 1,077,545 bytes
- 샘플 생성: 원본 전체에서 균등 간격 81프레임을 선택하고 960×540으로 변환
- 비교 조건: 두 요청에 동일한 81프레임 사용, raw frame SHA-256 일치 확인
- 요청 횟수: 총 2회
  1. mp4v 1회
  2. H264 600 kbps 1회
- 엔드포인트: `http://203.249.90.3:8031/analyze-video`
- HTTP 형식: `POST multipart/form-data`
- 폼 필드: `video`, `drone_id=DR-01`, `anomaly_score=0.654321`
- `anomaly_score=0.654321`은 전송 경로 검증용 합성 시험값이며 VadCLIP 실측값이 아니다.

## 2. 실행 위치와 안전 범위

- Jetson 격리 경로: `/tmp/h264_600_reapply_20260930/`
- 후보 uploader와 H264 worker만 사용한다.
- 운영 checkout 파일은 수정하지 않는다.
- CSI 카메라를 열지 않는다.
- main.py, hover, 비행 명령, 스트리밍 프로세스를 실행하지 않는다.
- `dae_*` 프로세스를 종료하거나 변경하지 않는다.
- 각 요청은 별도 프로세스에서 순차 실행한다.
- 실제 전송은 `--execute --execute-confirm P0-7-APPROVED-2-REQUESTS`가 동시에 있어야 가능하다.

## 3. 측정 항목

각 요청에 대해 다음 시간을 Unix timestamp와 elapsed seconds로 기록한다.

- 인코딩 시작·완료·소요시간
- HTTP 요청 시작·응답 완료·소요시간
- 인코딩부터 응답 완료까지 전체 시간
- 출력 파일 크기, SHA-256, codec, 해상도, fps, 프레임 수, 길이
- HTTP 상태 코드, 응답 헤더, 응답 JSON 원문

서버에서는 가능한 범위에서 다음 시각을 대조한다.

- 요청 수신 시작 또는 수신 완료
- VideoMAE 분석 시작·완료
- 최종 결과 생성·응답
- 생성된 event ID

관제 화면에서는 두 event의 영상, VideoMAE 결과, `anomaly_score=0.654321` 표시 여부를 확인한다.

## 4. 사전 점검

실제 요청 직전에 다음을 한 번씩 확인한다.

1. 관련 main/test/H264 worker 잔존 프로세스가 없는지 확인
2. `tegrastats` 1회로 RAM과 lfb 확인
3. 대상 영상의 크기·프레임·길이 재확인
4. 후보 해시와 승인 manifest 일치 확인
5. 두 모드 dry-run의 sampled raw SHA-256 일치 확인

메모리 연속 블록이 회복되지 않았거나 후보 해시가 다르면 전송하지 않는다.

## 5. 중단 조건

- 승인된 영상·횟수·엔드포인트와 실행 인자가 다름
- 두 모드 raw frame SHA-256 불일치
- 출력이 81프레임이 아니거나 ffprobe 실패
- HTTP 실패 또는 응답 JSON 파싱 실패
- 서버가 영상을 처리하지 못함
- 첫 요청 뒤 Jetson 자원이나 프로세스 상태가 정상으로 돌아오지 않음

재시도는 자동으로 하지 않는다. 실패하면 원시 로그를 보존하고 원인을 먼저 분석한다.
