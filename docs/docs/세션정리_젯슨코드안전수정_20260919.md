## 반영 내용

1. 비행 명령을 generation과 Future로 추적해 `PAUSE_PATROL`, `CANCEL_PATROL`, `LAND`, `EMERGENCY_STOP`, 이상 감지 호버가 진행 중 일반 명령을 선점하도록 변경했다. 미션 업로드·arm·takeoff·start 사이에도 취소 여부를 확인한다.
2. 이상 감지 프로세스가 MAVSDK를 직접 호출하던 구조를 제거했다. `main.py`가 고유 요청 ID를 원자적으로 기록하고 `command_receiver.py`가 hold 결과와 `PAUSED` 상태를 함께 확정한다. `LANDING`, `IDLE`, 배터리 복귀 중 요청은 거부한다.
3. 배터리 raw 단위를 `BATTERY_REMAINING_UNIT=auto|fraction|percent`로 명시할 수 있게 했다. 관측값 `96.0`은 percent로 잠그며 NaN, Inf, 음수, 범위 초과를 거부한다. 값 없음 `-1.0`은 RTL 판정과 텔레메트리에서 건너뛰고 경고를 30초로 제한한다.
4. 재시작 시 실제 `armed/in_air`를 읽어 지상 비무장이면 `IDLE`, 공중이면 `PAUSED + PROCESS_RESTART_RECOVERY`로 복구한다. 상태를 읽지 못하면 임의로 IDLE을 쓰지 않는다.
5. LAND 실패 시 이전 상태로 복원하고, kill 성공이 확인되지 않으면 IDLE로 보고하지 않는다. 미션 완료·스테이션 도착 뒤 hold가 실패하면 완료 콜백을 내보내지 않는다.
6. `alt_agl + ground_elevation_m - home_absolute_altitude_m`로 PX4 홈 기준 상대고도를 계산한다. 지면고도가 있는데 홈 절대고도를 읽지 못하면 미션 시작을 거부한다.
7. VadCLIP feature, probability, 최종 score의 NaN/Inf를 추론 오류로 처리한다.
8. 경로·스테이션 수신 즉시 `hasRoute/hasStation`을 갱신한다. 공유 JSON은 임시 파일+fsync+replace와 프로세스 간 파일 잠금을 사용한다. 이전 스트림 세션의 401/410/무응답 결과가 새 세션을 끄지 못하도록 stream ID 조건부 갱신을 적용했다.
9. 테스트 영상 요청에 ID, TTL, duration 상한, 소비 상태를 추가했다. 전체 영상을 메모리에 미리 적재하지 않고 `VideoCapture`로 필요한 프레임만 읽는다. 재시작 뒤 이미 소비했거나 만료된 요청은 재실행하지 않는다.
10. 업로드 슬롯을 snapshot 생성 전에 확보하고 종료 뒤 프레임 참조를 해제한다. 인코딩 실패 경로의 임시 파일을 정리한다.
11. `RESUME_PATROL`은 PX4에 순찰 미션이 남아 있으면 현재 index부터 재개한다. 귀환 미션이 순찰 미션을 덮었으면 저장한 순찰 index부터 남은 경로를 다시 구성한다.
12. `START_PATROL`에 경로가 없으면 제자리 이륙하지 않고 거부한다. 스트림 해상도, fps, quality, stream ID, upload path를 검증한다.

## 남은 검증

- 실제 Pixhawk `hover_now()` 경로와 이상 감지→hold→PAUSED→RESUME 통합 시험은 수행하지 않았다. 지상 안전 조건과 관제·비행팀 합의 후 진행한다.
- 배터리 센서가 현재 `remaining_percent=-1.0`, 전압 약 `5.635V`를 보고해 실제 임계값 전후 RTL 시험은 수행하지 않았다. 정상 배터리 텔레메트리 복구 후 단위 로그를 먼저 확인한다.
- `ANOMALY_THRESHOLD=0.4073`은 변경하지 않았다. 실제 드론 데이터 calibration이 필요하다.
- 실제 서버 영상 스트림 401/410 세션 경합, 실제 이상 영상 업로드, 장시간 온도·메모리 시험은 별도 E2E로 진행한다.
- 새 `start_all.sh`/`stop_all.sh`는 `bash -n`을 통과했으나, 전체 파이프라인을 불필요하게 재시작하지 않기 위해 실운영 실행 시험은 하지 않았다. 개별 프로세스 교체는 `restart_component.sh`로 확인했다.
