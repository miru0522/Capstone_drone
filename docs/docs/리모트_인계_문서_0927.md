| `/tmp` | `/tmp` | 1.451초 | 기준 |
| `/dev/shm` | `/tmp` | 1.209초 | 16.69% 단축 |

## Jetson에서 확인한 조건

- `/tmp`는 루트 ext4
- `/dev/shm`은 3.3GiB tmpfs, 확인 당시 3.3GiB 가용
- 기본 업로드 크기 960×540×3×48 = 74,649,600B, 약 71.19MiB
- raw와 최소 여유 64MiB 합계는 약 135.19MiB
- persistent worker encode는 lock으로 직렬화되므로 정상 상태의 활성 raw job은 1개

기존 state는 ext4의 `/tmp`에 있었으므로 `/dev/shm` 이동은 재부팅 후 `consecutive_failures`가 사라지는 실제 의미 변화다. 이 값은 자동 롤백이 아니라 `h264_rollback_recommended` 경보용 보조 지표다. 현재 정책은 영속 main 로그를 장애 증거로 사용하고 재부팅 간 카운터 연속성은 포기한다.

재부팅 간 경보 연속성이 필요해지면 성공 hot path에는 ext4 쓰기를 넣지 않는다. 두 번째 연속 실패로 rollback 권고가 처음 발생할 때만 ext4 durable marker를 기록하고, 시작 시 이를 읽어 state를 재시딩하는 후속 설계를 사용한다.

7. 1.2Mbps/4Mbps/mp4v PSNR·SSIM 및 서버 판정 비교
8. `/dev/shm` ENOSPC 실패 주입과 재시작 후 상태 정책 확인
9. 종료 후 raw/response/lock orphan 0개 확인

## 통과 기준

- mp4v 대비 H264 p50·p95 각각 20% 이상 단축
- 영상별 H264 p95가 mp4v보다 악화되지 않음
- H264 100회 성공 100%, 손상·빈 MP4 0
- 예기치 않은 persistent worker 재시작 0
- uploader/worker 각각 fd와 thread가 warm 기준 +2 이내, RSS +100MiB 이내
- 첫 25회 대비 마지막 25회 p95 증가 10% 이내
- response 기록 p50 증가 10ms 이내
- orphan 0
- 잠정 품질 기준 PSNR 30dB 이상, SSIM 0.95 이상
- 서버 최종 판정 일치 100%
- anomaly score 차이 중앙값 0.02 이하, p95 0.05 이하
- ENOSPC는 timeout 전에 명시적으로 실패하고 partial MP4가 없어야 하며, 공간 복구 후 다음 job이 성공하고 state가 `ok`여야 함

하나라도 실패하면 H264 운영 전환을 보류하고 `CLIP_ENCODER=mp4v`를 유지한다. 품질 기준만 실패하고 서버 판정 기준은 통과하면 1.2→2→4Mbps 순서로 재시험해 모든 기준을 만족하는 최저 bitrate를 선택한다.
