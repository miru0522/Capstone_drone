# H264 하드웨어 인코더 구현 Claude 2차 검수

## 판정

**조건부 승인. 코드 레벨 MUST 없음.**

1차 MUST였던 다음 세 항목은 코드와 Jetson 실기 증거로 모두 해소됐다고 판정했다.

1. `PR_SET_PDEATHSIG(SIGTERM)`과 부모 PID 재확인으로 고아 worker 방지
2. 검증 prototype과 동일한 `is-live=true` GStreamer pipeline 복원
3. 연속 실패·worker/job 수·2회 실패 시 `rollback_recommended` 상태 기록

지속 worker는 이벤트별 subprocess가 성능 게이트를 실패한 뒤에만 추가됐고,
프로세스만 유지하며 pipeline은 이벤트마다 새로 만드는 최소 구조라 과도한 복잡성이
아니라고 평가했다. timeout이면 worker 전체를 종료하므로 늦은 응답이 다음 요청과
섞이지 않으며, raw/partial/final/response 파일도 예외 경로에서 정리됨을 확인했다.

## SHOULD

- worker append 로그의 크기 제한 또는 회전
- 10ms 응답 파일 polling을 이벤트 방식으로 개선
- MP4 출력 임시 디렉터리 여유 공간도 방어적으로 확인
- Linux `PR_SET_PDEATHSIG`가 생성 스레드 종료에도 반응하는 특성 문서화

위 항목은 배포 차단 사유가 아니다.

## 코드와 별개인 운영 전 검증 게이트

- 지속 worker 100회 p95 및 30분 이상 자원 추세
- 필요 시 2시간 연장 시험
- 4Mbps/1.2Mbps 서버 판정 품질과 실제 종단 업로드 지연 비교
- `CLIP_ENCODER=mp4v` 재시작 롤백 실검증
- timeout 기준 확정

따라서 현재 코드는 검증 단계로 진행할 수 있지만 Jetson 운영 교체 승인은 아직 아니다.
