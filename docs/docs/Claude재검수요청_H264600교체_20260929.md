# H264 600 kbps 교체 준비 2차 검수 요청

이전 검수 세션 `29f689fd-fb05-410f-bf28-4f0e33e9b2be`의 MUST 5건을 커밋 `a86f543`에 반영했습니다. 운영 Jetson 파일 복사·재시작과 서버 재전송은 하지 않았습니다.

다음을 저장소 원문과 원시 자료에서 다시 확인해 주세요.

1. `.gitattributes`의 LF 고정, 갱신된 manifest SHA-256과 Jetson 격리 preflight 원본 출력이 일치하는지
2. 운영 기준 `baseline/main.py`와 인코더 로그만 추가한 `candidate/main.py`가 배포 집합·manifest·preflight에 포함됐는지
3. 종단 지연 게이트 철회가 연구 문서와 채택 문서에 투명하게 기록됐고 종단 개선 주장이 남아 있지 않은지
4. 실제 `CLIP_ENCODER=mp4v` 재시작 리허설이 H264 활성화 전 필수 중단 게이트로 배치됐는지
5. 서버 판정 원시 JSONL과 traceback이 커밋됐고, 재집계가 28/30·미커버·카테고리 변경을 정확히 공개하는지
6. 새 preflight가 `import gi`, 잔존 worker, `/dev/shm`, PID 파일, 메모리/공유 메모리를 검사하는지
7. 후보 코드·절차에 새 배포 차단 문제가 없는지

이번 요청의 승인 범위는 **정적 교체 준비 번들과 승인 후 실행 절차**입니다. 실제 mp4v 재시작 리허설과 H264 활성화는 운영 변경이므로 사용자 별도 승인 후 절차 안에서 실행됩니다. 동적 게이트를 승인 없이 실행하지 않은 사실 자체를 결함으로 판정하지 말고, 게이트의 위치·중단 조건·검증 항목이 충분한지 평가해 주세요.

판정은 첫 줄에 `APPROVED` 또는 `REVISE`로 명확히 적어 주세요. `REVISE`이면 배포 전에 고쳐야 할 MUST만 번호로 제시해 주세요. 코드나 파일을 수정하지 말고 읽기 전용으로 검수해 주세요.
